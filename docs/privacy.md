# Privacy

OpenGaze processes images of people's eyes and faces, which is biometric data. The defaults keep
that data on the Mac and short-lived.

## What is true today (Phase 1)

- **Local processing only.** Camera frames are processed in memory. Nothing is sent over the network.
- **No recording.** No camera image is written to disk. `privacy.allow_recording` defaults to
  `false`, and no recording feature exists yet.
- **No cloud features.** The Claude, Cartesia and Convex modules haven't been built yet.
  `privacy.cloud_features_enabled` defaults to `false`.
- **No credentials in the repository.** `.env` is git-ignored. `.env.example` lists the variables,
  all empty.
- **Non-live data is labeled.** Synthetic and recorded sources are marked in every `CameraFrame`
  (`source_kind`) and in the UI, so they can't be mistaken for live tracking.
- `demo/synthetic_eye.avi` is generated by `scripts/make_synthetic_recording.py` and contains
  rendered images, not a real person.

## Rules for later phases

These are design constraints, not features that exist yet:

1. Saving video needs `allow_recording: true` **and** explicit consent in the UI each session, with
   a visible recording indicator.
2. Raw webcam or eye-camera images are never sent to any cloud API.
3. Cloud features are opt-in. Only text the user explicitly approves is sent (to Claude for
   rewriting, to Cartesia for speech). Convex receives only user-approved messages and non-sensitive
   device status.
4. Calibrations, which store eye-feature statistics, stay in a local, git-ignored `data/` directory.
5. The cursor system must keep working with no network connection.

OpenGaze is a hackathon prototype. It is **not a medically validated assistive device**.
