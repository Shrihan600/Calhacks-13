# Privacy

OpenGaze processes images of people's eyes and faces, which is biometric data. The defaults keep
that data on the Mac and short-lived.

## What is true today (Phase 1)

- **Local processing only.** Camera frames are processed in memory. Nothing is sent over the network.
- **No recording by default.** No camera image is written to disk unless
  `privacy.allow_recording: true` is set *and* the session is started with
  `opengaze run --record-video`. While it records, the window shows **● REC VIDEO**. Sessions
  (eye video, calibration, trace) go to `~/.config/opengaze/sessions/`; delete the folder to
  delete the recording.
- **Traces hold features, not images.** `opengaze run --trace` writes eye-feature values,
  gaze positions and cursor positions per frame to `~/.config/opengaze/traces/`. That is
  still eye-movement data: keep traces local like calibrations.
- **Cloud features are opt-in.** `privacy.cloud_features_enabled` defaults to `false`. The only
  cloud feature built so far is Cartesia voice (`opengaze/voice/`). It runs only when that flag
  is `true` (or `--cloud` is passed) *and* `CARTESIA_API_KEY` is set. Then:
  - The microphone opens only when the user activates `MIC`, a red indicator shows while it
    listens, and it closes automatically after a pause (20 s hard cap). The recording is held in
    memory, sent to Cartesia `/stt`, and discarded. It is never written to disk.
  - Only text the user activates `SPEAK` on (or selects and triggers ⌃⌥S on, in the voice bar)
    is sent to Cartesia `/tts/bytes`. The returned audio is written to a temp file for `afplay`
    and deleted when playback ends or stops.
  - The system-wide voice bar reads the selection by sending ⌘C, then restores the previous
    clipboard text.
  - With the flag off or no key, `SPEAK` uses the on-device macOS voice and nothing is sent.
- **No credentials in the repository.** `.env` is git-ignored. `.env.example` lists the variables,
  all empty.
- **Non-live data is labeled.** Synthetic and recorded sources are marked in every `CameraFrame`
  (`source_kind`) and in the UI, so they can't be mistaken for live tracking.
- `demo/synthetic_eye.avi` is generated by `scripts/make_synthetic_recording.py` and contains
  rendered images, not a real person.

## Rules for later phases

These are design constraints, not features that exist yet:

1. Saving video needs `allow_recording: true` **and** explicit consent in the UI each session, with
   a visible recording indicator.
2. Raw webcam or eye-camera images are never sent to any cloud API.
3. Cloud features are opt-in. Only text the user explicitly approves is sent (to Claude for
   rewriting, to Cartesia for speech). Convex receives only user-approved messages and non-sensitive
   device status.
4. Calibrations, which store eye-feature statistics, stay in a local, git-ignored `data/` directory.
5. The cursor system must keep working with no network connection.

OpenGaze is a hackathon prototype. It is **not a medically validated assistive device**.
